Guardian is a local-first, read-only tool for checking the configured publication policy of a repository and producing a result tied to the exact revision inspected. Its job is to reveal what the evidence supports—and what it does not.

A useful result has a precise meaning

Three outcomes. No invented green.

Guardian evaluates a selected repository against its configured policy. A successful run is a narrow technical receipt, never general approval to publish.

01 / VERIFIED

The configured checks passed.

All required checks completed successfully for the inspected revision. This is not a guarantee that the project is secure, compliant, correctly licensed or appropriate for public release.

02 / ACTION REQUIRED

A stated rule was not satisfied.

A required check found a policy violation. Review the specific evidence, correct the cause and verify the intended revision again.

03 / INDETERMINATE

The evidence is incomplete.

At least one required check could not complete reliably. Unknown never becomes a pass; investigate before drawing conclusions.

The publication boundary

Inspect. Classify. Preserve.

Identity, local environment, tracked inventory, secret patterns and source provenance are evaluated against an explicit policy. Guardian does not modify the target repository during ordinary verification.

  1. Choose the exact source revision and configured release policy.
  2. Run the read-only CLI checks.
  3. Read the result and any missing evidence.
  4. Save an optional receipt outside the checked repository.
  5. Make a separate, authorized publication decision.

Verification is evidence. Authority remains human.

Guardian does not inspect every historical PR, attachment, image or legal right; it does not conduct browser-based UX acceptance, certify cybersecurity, or authorize a visibility change. Publication requires its own rights, history, identity and owner approvals.
